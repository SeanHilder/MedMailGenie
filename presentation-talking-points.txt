SLIDE 11 — REQUIREMENT 6 (about 60–80 seconds, including demo)
On-slide layout: what is extracted | calendar hand-off | why it matters.

- Link from the previous speaker: “We have handled the reply. What about
  the follow-up work inside that email?”
- Explain the user need: a healthcare administrator may have a stock report
  to prepare, a deadline and a meeting buried in the same conversation.
- R6 extracts those items automatically when the extension analyses the
  email. The current code considers the thread and asks the model to use
  the latest agreed meeting time, excluding completed or cancelled tasks.
  This is model-guided behaviour, not a guarantee of perfect accuracy.
- “Add to calendar” opens Google Calendar with a title and start/end time.
  The user checks the details and clicks Save. We do not silently book it.

Live demo: open a prepared fictional email with a task, an explicit deadline
and a meeting date/time. Show Tasks & Deadlines, click Add to calendar,
then point out the prefilled details and the Save button. Check the date,
time and calendar time zone. Rehearse this exact example before presenting.

QUICK Q&A CUES
- Gmail/Calendar API? The extension reads Gmail’s page; the calendar action
  builds a Google Calendar URL. No direct Calendar API booking is used.
- Missing or uncertain dates? The prompt asks the model to omit calendar
  events when a date cannot be resolved. If duration is missing it assumes
  one hour, so the user must check the proposed event before saving.
- Validation? The backend checks output structure; it does not prove the
  extracted meaning is correct. Testing with realistic examples is needed.
